# 闭卷重写复现笔记

记录 2026-09-03 独立复现重写中真正学到的不变量、失败模式和验证证据。
这是学习记录，不是新研究证据；证据等级以 results/ 冻结 artifact 为准。
代码见 [experiments/rewrite/](../experiments/rewrite/)。

## 第 1 步：exact FP32 oracle

- **E = Σδ_v 为什么精确成立**：加法是线性的，每个内部节点算的是
  「子树真和 + 之前累积的误差」再加一个新的局部舍入 δ_v。误差原样上传、不放大也不缩小，
  到根即 E = Σδ_v。这条恒等式是后续 A/C 分解与全部 predictor 标签的基础。
- **tie 规则**：把 value/量子 取整时，正中间取偶数。实现直接依赖 Python 对 Fraction
  调 `round()` 的 half-to-even 语义，而不是手写三分支；靠的是标准库行为，测试里用
  1.5 ULP 与 1.25 ULP 两个用例区分 tie 与非 tie。
- **进位不是溢出**：有效数字舍入后达到 2^24 时，`s_rounded * 量子` 自然落进下一个 binade，
  用 Fraction 表示无需任何特殊处理。真正的溢出只在结果超过 MAX_FINITE 时抛 OverflowError。
- **输入合同**：oracle 只对加法舍入负责，不记输入表示误差。若叶子是 1/3 这类不可表示的数，
  它变成 FP32 时的量化误差不属于任何 δ_v，会让 E = Σδ 断裂。因此 `reduce_tree` 用
  `is_stored_fp32` 把关，非 FP32 叶子直接拒收。
- **验证**：对照旧 oracle 两万对随机加法（含次正规、宽指数差、近溢出带、20% 强制 tie）
  与 40 棵随机树逐节点一致；另有对照 NumPy 硬件 float32 的差分测试。第一次实现即通过。

## 第 2 步：A/C 分解与 C 主导

- **E² = A + C** 只是平方展开：A = Σδ_v² 是局部能量（恒非负），
  C = 2Σ_{u<v} δ_uδ_v 是符号相干项（可正可负）。乘数 2 来自交叉项 δ_uδ_v 在
  n×n 展开里出现两次。
- **前缀和技巧**：C 的显式配对和有 n(n-1)/2 项，按较大下标 v 分组后
  C = Σ_v 2·δ_v·(排在 v 前的 δ 之和)，一趟前缀和即 O(n)。两行的顺序不能对调：
  必须先用旧 prefix 配当前 d，再把 d 并入 prefix，否则多出一个自配对项。
- **C 主导的含义**：固定输入换树，A 几乎是常数（由节点和的 binade 决定），
  树好坏几乎全体现在 C 上。宽度 256 上跨 32 棵树的 std(C)/std(A) 实测 2.5 到 3.6。
- **为什么便宜分数不稳定**：任何只看 δ 幅度的分数最多估到 A，而真正区分树的是 C 的符号，
  符号来自「精确和落在舍入格点上方还是下方」，对输入每一位敏感，静态特征看不见。
- **验证**：与 reduction_analysis 的 A/C 在 30 个案例上逐值精确相等（Fraction）；
  复现的 std(C)/std(A) 与旧实现四个输入种子完全一致（3.531, 2.550, 3.120, 3.609）。

## 第 3 步：受控生成器与冻结 seed

- **RNG 是共享的流**：`random.Random` 是一条流，不同方法取走的比特数不同
  （randint 少、randrange 多，都可能拒绝重采样）。调用顺序、shuffle 的位置、
  移除元素的顺序都改变后续每一次抽样，所以它们是冻结边界的一部分，不是自由细节。
- **树良构性不变量**（`check_tree_structure`，本步唯一的研究核心）：L 个叶子的满二叉树有
  L-1 个内部节点；除根外每个下标恰好被用作孩子一次，根不被用作孩子；每个父节点下标严格大于
  两个孩子下标（等价于 `Tree` 的正序求值合同）。下标顺序是序列化选择，不是深度顺序。
- **验证**：三个生成器与旧实现逐节点、逐值一致；并从 seed 出发精确重建 2026-08 冻结 v2 的
  全部 192 个输入组 stored_leaf_bits 与 12288 个 graph_sha256。

## 第 4 步：Q_8/12 macro 分数与 shortlist

- **Q 估的是 A**：Q = Σ_{root band 前 8 节点}(ulp(子树和)/ulp(根))² / 12，只看每个节点的 ULP
  幅度，是 E²=A+C 里 A（局部能量）的估计，对符号相干项 C 完全失明。
- **root band 为什么按子树叶子数**：这是纯结构量，只看树形不看数值，因而便宜（选哪 8 个节点
  无需先算精确和）；叶子最多的节点累加项最多、子树和幅度最大、ULP 最大，能量贡献也最大，
  它们聚在根附近。深度不行（不平衡树里深节点子树可能很小）；按 ULP 大小要先算精确和，
  就不再是纯结构的廉价选择。
- **为什么 Q 排序不稳定**：固定输入换树，A 几乎是常数，真正在树间变化、决定排名的是 C。
  Q 只看得见 A，盯着不变量、错过了变量，所以排序不稳。
- **两个复现中引入的 bug（差分测试才抓到，结构测试挡不住）**：
  1. root band 的 `size(index)` 误减了一次 leaf_count；`subtree_leaf_counts` 已按全局下标索引，
     多减后取到叶子（值恒 1），堆退化成按下标选，root band 全错，q_score 全偏。
  2. full_q 用手写 `+=` 循环累加，与冻结 CSV 用的内置 `sum()` 不一致：Python 3.12+ 的 `sum()`
     对 float 采用 Neumaier 补偿求和，255 项累加下最后一位不同。浮点求和不仅对顺序敏感，
     对求和算法同样敏感。
- **范围**：只闭卷重写 Q 分数与 shortlist；B=3 联合 cell beam 依赖运行时训练的 numpy probe，
  属工程管线，由 test_predictor_fixed_k8_beam_inference 的 8-ULP 测试独立守住，本次不重写。
- **验证**：全部 192 组、每组 64 棵树逐值复现冻结 v2 的 fixed_q_score、fixed_energy_capture、
  shortlisted、q_selected。
