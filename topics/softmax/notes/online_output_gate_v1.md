## 推进顺序与门槛

1. **输出影响门槛**：在 CPU 上扩展固定叶块的 (m,ell) 为 (m,ell,O)，计算 y=O/ell。
   同时观察分母、分子及最终除法，先回答“误差是否传导、抵消或被放大”。
2. **固定方案比较**：同一份 logit、V、叶块和算术设置，比较 chain、balanced 和
   组内 chain/组间 balanced。先做数值探索与资源估算，再选少量方案上 GPU。
3. **硬件可行性**：用实际 kernel 核对算术与 dump；成本比较同时看寄存器/共享内存、
   partial 写回和读取、同步、kernel launch、占用率及实测耗时。
4. **优先固定策略**：若一个固定分段规则在预先规定的输入范围和输出容差内足够好，
   且成本可接受，就先采用它。不能由有限测试称其“普遍够好”。
5. **条件性 selector**：只有出现可重复、工程上有意义的方案优劣交叉，且选择收益
   超过特征采集与切换成本时，才研究廉价选择指标。

逐族结果、失败样例与成本/误差权衡仍要保存；暂停平均 D 确认不等于免除证据要求。
可接受输出误差和成本门槛须在工程验证前明确，不能看过数值后倒填。

## 为什么必须联动分子与分母

本项目定义未归一化分子 O，最终输出 y；文献可能以 O 表示最终输出，阅读时要区别。

设共同 real-exp 参照为 O_star、ell_star，y_star=O_star/ell_star；
DeltaO=O_hat−O_star，Deltaell=ell_hat−ell_star。在最终除法舍入前逐分量有

```
O_hat / ell_hat - y_star = (DeltaO - y_star * Deltaell) / ell_hat
```

最终还要加上一次除法的舍入残差。因此分母误差本身不能决定输出误差；
分子与分母误差的相关性和 V 的符号/尺度都会影响结果。

可保存四种诊断值：O_star/ell_star、O_star/ell_hat、O_hat/ell_star、O_hat/ell_hat，
以及最终舍入输出。中间两个是只替换一侧的反事实，不是实际 kernel 输出，也不能把
两个反事实绝对误差简单相加当成总误差。

**首个对照取所有 V=1。** 初始 O_b=ell_b；若两个通道使用完全相同的权重、
乘加顺序和舍入，则归纳可得每个节点 O_hat=ell_hat，有限正分母下最终比值为 1。
即使 ell_hat 有误差，输出也能精确正确。这是指定 CPU 合同下的结构性质，
不是对所有混合精度 attention kernel 的承诺。

V=0 是零输出检查；正负 V 是抵消检查；块指示 V 用于观察块概率质量的误差。
不能只测 V=1 就宣布输出不受影响，也不能只测分母反事实就宣布 attention 受损。

## 首个最小输出合同（待实现）

- 先单 query、标量 V；首轮沿用每块 32 个相同 logit，且块内 V 相同，
  V_b 取 {0, ±1/2, ±1}，于是 ell_b=32、O_b=32 V_b 的叶内累加可精确实现。
  首轮不包含 QK matmul、一般 PV matmul、mask/dropout、反向传播或模型质量指标。
  标量探针只是机制检查；工程重要性还需向量及代表性实际输入。
- 固定同一批叶输入，先复用已存 pilot 输入做事后扩展；V 模式与后续新输入设计
  在查看输出结果前写入预测/配置。明确这一批仍是探索性。
- (m,ell) 使用现有已验证的 merge；O 通道复用该次 dump 的实际权重及有序树，
  separate 为两乘一加，FMA 分支与现有 merge 的胜方选择一致。
  这与同时执行的三元状态在权重不依赖 O 的当前合同下等价，需以测试守住。
- 末尾以 `RN32(O_hat/ell_hat)` 定义 CPU 除法；不能直接冒称它等于目标 kernel 的
  reciprocal/mul、approx-div 或输出 cast 路径。GPU 阶段另行核对实际指令与存储 dtype。
- 参照使用 exact logit 差的 real-exp 区间；O_star 允许为负，乘负 V 时端点方向必须交换。
  一般 O/ell 区间可保守外包；已知恒等式的 V=1 对照应单独精确核对，避免忽略相关性。
- 先报告绝对输出误差，并在 V 非全零时报告按 max|V| 归一化的绝对误差；
  输出接近零时不以相对输出误差作主指标。向量阶段扩展到明确的范数。
  FP32 误差、最终低精度 cast 后的变化与任务重要性分层解释。

新核心仍由用户写：有符号 O 传播、real-exp 分子区间、输出误差分解；agent 搭载荷、
runner、结构生成器、确定性反例和审计。先完成这个最小合同，不再插入统计学习练习。

## 分段树与成本必须分别验证

仓库现有 `schedules.split_k(N,splits)` 是组内 chain、组间 chain；不是组间 balanced。
必须另建有明确名称的图生成器，保留原函数及旧图快照的语义。

N=2048 个叶块，每组 g=32，组数 64：

| 图 | 最长路径的 merge 次数 | 总 merge 次数 |
| --- | --- | --- |
| chain | 2047 | 2047 |
| balanced | 11 | 2047 |
| 现有 split_k(2048,64) | 94 = 31+63 | 2047 |
| 拟新增组内 chain、组间 balanced | 37 = 31+6 | 2047 |

不将深度缩短直接解释为误差保证、运算总数减少或运行时间加速。
同一 CTA 内分段、跨 CTA 拆分和多 kernel 合并有不同资源与通信成本，不能只标一个树名。
例如把每组 FP32 (m,ell,O) 全部写入全局内存、O 维度为 d 时，64 组的 partial 载荷为
64×(d+2)×4 字节；若全部写一次再读一次，仅这部分流量为两倍，尚不含其他输入、输出、
对齐或调度开销。这只是指定布局的资源核算，不是 GPU 测速。

硬件设计应参考已有工作，不能把分段合并本身当作新颖性。FlashAttention 强调 IO，
FlashAttention-2 强调非 matmul 开销、占用率与线程分工/共享内存通信；这些都说明
“树更浅”不足以判断 CUDA 成本。见[FlashAttention](https://arxiv.org/abs/2205.14135)、
[FlashAttention-2 §3](https://arxiv.org/html/2307.08691v1#S3)。

当前不租卡、不宣称加速；先完成 CPU 输出门槛与候选结构，再把 2a dump 协议扩展到 O。
分段参数与最小有意义输出差距尚未冻结。
