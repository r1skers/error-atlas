## 为什么必须联动分子与分母

本项目定义未归一化分子 O，最终输出 y；文献可能以 O 表示最终输出，阅读时要区别。

设共同 real-exp 参照为 O_star、ell_star，y_star=O_star/ell_star；
DeltaO=O_hat−O_star，Deltaell=ell_hat−ell_star。在最终除法舍入前逐分量有

```
O_hat / ell_hat - y_star = (DeltaO - y_star * Deltaell) / ell_hat
```

最终还要加上一次除法的舍入残差。因此分母误差本身不能决定输出误差；
分子与分母误差的相关性和 V 的符号/尺度都会影响结果。

可保存四种诊断值：O_star/ell_star、O_star/ell_hat、O_hat/ell_star、O_hat/ell_hat，
以及最终舍入输出。中间两个是只替换一侧的反事实，不是实际 kernel 输出，也不能把
两个反事实绝对误差简单相加当成总误差。

**首个对照取所有 V=1。** 初始 O_b=ell_b；若两个通道使用完全相同的权重、
乘加顺序和舍入，则归纳可得每个节点 O_hat=ell_hat，有限正分母下最终比值为 1。
即使 ell_hat 有误差，输出也能精确正确。这是指定 CPU 合同下的结构性质，
不是对所有混合精度 attention kernel 的承诺。

V=0 是零输出检查；正负 V 是抵消检查；块指示 V 用于观察块概率质量的误差。
不能只测 V=1 就宣布输出不受影响，也不能只测分母反事实就宣布 attention 受损。

## 概率与 V 的分工、首轮模式（输出运行前写定）

常值块内每个 token 的概率相同，但不同块的概率一般不同。实数参照为

```
p_(b,i) = exp(m_b-M) / ell_star                 # 块内单个 token
P_b = n_b * exp(m_b-M) / ell_star               # 整块概率质量
y_star = sum_b P_b * V_b
```

P_b≥0 且 sum_b P_b=1；V_b 是被加权的标量值，允许为负，不需要归一化。
V=1 不是给每个 token/块相同概率；它是给各位置相同的值。
用户对两块 P=(0.8,0.2)、V=(1,-1)/(1,1) 的手算回答为“0.6，1”，正确。
这是概念练习，不登记为未见数据的研究方向预测。

首轮沿用 64 族、chain/balanced、separate/FMA，共用以下 5 个固定 V 模式：

| 名称 | V_b 的规定 | 用途 |
| --- | --- | --- |
| zero | 全 0 | 零通道检查 |
| one | 全 1 | 分子分母同步的结构检查 |
| max_block | 原输入次序中第一个最大 logit 块取 1，其余 0 | 最大块的概率质量 |
| first_block | 原输入第 0 块取 1，其余 0 | 固定位置的概率质量，不挑结果最大的误差 |
| alternating_sign | 原输入偶数索引 +1、奇数索引 -1 | 正负分子与抵消 |

模式按原始输入定义，不随 schedule 重排或 FMA 改变；max_block 与 first_block 重合时
保留两条预定记录，不把它们当独立样本。模式本身不是随机概率分布，不按结果追加模式。
计划最多 64×5×2×2=1280 条 online 输出记录，实际 runner 与输出参照尚未实现，研究轮未运行。

Agent 的运行前预期：zero/one 是精确控制；非恒定 V 可能表现出不同的误差传导和抵消，
不预言所有族的 chain 输出都更差。输出是否值得工程投入仍按已写定的用途门槛判断。

当前学习入口是 `output_probe.propagate_numerator`：读取已有 dump 权重和 O 子节点，
返回各内部节点的 O。局部叶初始化 O_b=n_b V_b，因为叶的局部尺度 exp(m_b−m_b)=1；
不要在叶子先乘 P_b 或全局 exp，否则沿树缩放会重复计算。最终除法/参考区间是下一小步。

### 首轮执行合同补充（查看输出研究数据前写定）

`output_runner` 将保存上述 1280 条 online 结果，同时延续已有固定贡献对照，增加
64×5×2=640 条 ordinary 结果。普通臂先取整项正确舍入的 c_hat_b，再对 c_hat_b V_b
作同图普通 FP32 加法；首轮 V 只有 0/±1，这个乘法精确。同一 ordinary 臂由两个 FMA 设置共用。
此处未新增输入、模式、图或硬件轴；固定臂仍是预知全局最大值的离线控制。

每条记录保存 O_hat、ell_hat、精确商、一次 RN32 后的值及除法残差，另存
DeltaO、Deltaell、O_star/ell_hat 和 O_hat/ell_star 两个反事实。反事实的绝对误差不能相加
当成实际误差预算。实际值和两种反事实都使用同一 real-exp 输出参考。

三个存储格式分别统计：FP32、FP32 输出再 RN-even cast 到 FP16、再 cast 到 BF16
（这里“再”均从 FP32 出发，不是 FP16 转 BF16）。FP16 用标准库 binary16 转换，
BF16 用 FP32 位模式的 round/sticky/parity 舍入；均采用 gradual underflow 和规范 +0。
首轮只接受 [-2,2] 内 stored FP32 输出，覆盖 |V|≤1 的探针并留出余量，超出直接失败。
这不是一般 NaN/溢出/负零模拟，也不冒称已核验 GPU 的实际存储算术。

每格报告最终绝对误差的 mean/max 数值区间、chain/balanced 误差差 D、正负方向族数、
输出位模式改变数；同时保存 online/ordinary 同树输出差。zero 模式的 max|V| 为 0，
归一化误差记为未定义，绝对误差仍正常记录。其余首轮模式 max|V|=1。

Agent 的运行前判断补充：zero/one 必须精确；非恒定 V 的输出可能保留部分路径差异，
不预言总体差距方向。预计低精度存储会减少发生位变化的对照数，但并不预言全部相同。
低精度翻位数量不能替代工程重要性判断。本轮结束后停止扩样，仍需应用场景/容差才进入工程分支。

## 分段树与成本必须分别验证

仓库现有 `schedules.split_k(N,splits)` 是组内 chain、组间 chain；不是组间 balanced。
必须另建有明确名称的图生成器，保留原函数及旧图快照的语义。

N=2048 个叶块，每组 g=32，组数 64：

| 图 | 最长路径的 merge 次数 | 总 merge 次数 |
| --- | --- | --- |
| chain | 2047 | 2047 |
| balanced | 11 | 2047 |
| 现有 split_k(2048,64) | 94 = 31+63 | 2047 |
| 拟新增组内 chain、组间 balanced | 37 = 31+6 | 2047 |

不将深度缩短直接解释为误差保证、运算总数减少或运行时间加速。
同一 CTA 内分段、跨 CTA 拆分和多 kernel 合并有不同资源与通信成本，不能只标一个树名。
例如把每组 FP32 (m,ell,O) 全部写入全局内存、O 维度为 d 时，64 组的 partial 载荷为
64×(d+2)×4 字节；若全部写一次再读一次，仅这部分流量为两倍，尚不含其他输入、输出、
对齐或调度开销。这只是指定布局的资源核算，不是 GPU 测速。

硬件设计应参考已有工作，不能把分段合并本身当作新颖性。FlashAttention 强调 IO，
FlashAttention-2 强调非 matmul 开销、占用率与线程分工/共享内存通信；这些都说明
“树更浅”不足以判断 CUDA 成本。见[FlashAttention](https://arxiv.org/abs/2205.14135)、
[FlashAttention-2 §3](https://arxiv.org/html/2307.08691v1#S3)。

当前不租卡、不宣称加速；先完成 CPU 输出门槛与候选结构，再把 2a dump 协议扩展到 O。
分段参数与最小有意义输出差距尚未冻结。
不能直接以 dtype 的 unit roundoff 替代最小有意义效应：极小扰动也能跨舍入中点改变
cast 位模式，而单个翻位又不自动意味着工程损害；例子及已知性门槛见上面的筛查笔记。
